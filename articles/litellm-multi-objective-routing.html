给 LiteLLM 加一个多目标路由策略：
四维加权评分 怎么设计

一句话结论LiteLLM（30k+ star 的 LLM 网关）官方路由策略都是单一目标：最低延迟、最低成本、最少负载。但生产里成本、延迟、稳定性往往互相冲突。我在 fork 里实现了多目标加权评分策略：延迟、成本、成功率、吞吐量四维指标，Min-Max 归一化后按可配置权重加权，让运维用权重表达业务偏好。18 个单测全过，代码在 github.com/Vanity-1/litellm（分支 feat/multi-objective-routing）。

1为什么需要多目标路由

LiteLLM 是生产级 LLM 网关，统一 100+ 模型的接口。它内置了多种路由策略，但都是单一目标：

策略优化目标局限
lowest-latency延迟最低可能一直选最贵的模型
lowest-cost成本最低可能一直选最慢的模型
least-busy负载最少忽略成本与质量

真实业务里这些目标经常互相冲突：要便宜就不能要最快，要稳定就得牺牲一点成本。单一目标无法表达「我 60% 在乎成本、30% 在乎延迟、10% 在乎稳定」这种权衡。多目标加权评分就是把这种业务偏好变成可配置的权重。

一个典型场景批量离线任务：延迟无所谓，成本敏感 → 权重偏向 cost。线上对话：延迟敏感，成本次要 → 权重偏向 latency。同一套网关，不同任务配不同权重，而不是为每个场景写死一套策略。

2核心设计：四维加权评分公式

评分公式很直观，难点在「怎么让不同量纲的指标可比」：

Score = w_latency × latency_score
      + w_cost × cost_score
      + w_success × success_score
      + w_throughput × throughput_score

四个指标量纲完全不同：延迟是毫秒级、成本是美元级、成功率是 0~1、吞吐是 TPM/RPM。直接加权没有意义，必须先归一化再加权。我用 Min-Max 归一化把每个指标压到 [0,1]：

  • 延迟 / 成本：越低越好，归一化后取反（1 - normalized），分数越高越优。
  • 成功率 / 吞吐：越高越好，直接归一化。
  • 权重自动归一化：四个权重总和自动归一为 1，全零权重回退默认值，避免配置失误。
为什么用 Min-Max 而不是 Z-Score指标量纲差异大（延迟毫秒级、成本美元级），Min-Max 能统一到 [0,1] 且保留相对排序；Z-Score 需要假设正态分布，对「延迟」这种长尾分布不合适。

3关键实现：指标采集、归一化、冷启动

评分需要实时指标，指标从哪来？LiteLLM 的 CustomLogger 钩子会在每次请求成功/失败后异步回调。我通过它采集每个部署的延迟、TPM/RPM 吞吐、成功/失败次数，写入 router 缓存，评分时读取。

三个工程细节决定策略能不能在真实环境用：

  • 冷启动：新部署没有历史数据，如果直接跳过，它永远没机会被选中、也就永远没有数据——死循环。处理：无历史数据的部署成功率默认 1.0（已通过健康检查），延迟/吞吐用 0 参与归一化，保证新部署有机会被选中。
  • TPM/RPM 限额约束：评分前先过滤超出限额的部署，防止把流量打到快超限的模型上。
  • 随机打破平局：同分部署随机选择，避免某个部署因排序稳定被长期选中、其他部署空转。

评分流程

1. 过滤
排除超限 / 不健康
2. 归一化
四维 → [0,1]
3. 加权
按权重求和
4. 选择
最高分，同分随机

4扩展点接入：与官方策略同构

LiteLLM 提供了 CustomRoutingStrategyBase 扩展点，官方 LAR-1 策略也基于它。我的实现完全走这个扩展点，不碰路由主流程：

  • 权重通过 routing_strategy_args 配置：weight_latency / weight_cost / weight_success_rate / weight_throughput。
  • 成本计算通过 litellm.get_model_info 解析，兼容 openai/ 前缀模型名。
  • 异步优先：指标采集依赖异步回调，同步接口显式抛 NotImplementedError，引导用户启用 async 模式——否则策略拿不到实时指标，评分就是空转。
为什么只支持异步指标采集依赖 CustomLogger 的异步回调，同步路由无法获取实时指标。与其让同步模式「假装能用」，不如显式报错，把用户引导到正确的 async 模式——这是设计上主动做的取舍。

5验证结果：18 个测试

路由策略是网关核心路径，必须用测试锁住行为。我写了 18 个单测，覆盖：

  • 权重归一化：任意权重组合自动归一为 1，全零回退默认
  • 纯成本路由：正确选择免费本地模型；云端模型对比中正确选择更便宜的 gpt-4o-mini
  • 纯延迟 / 纯成功率 / 纯吞吐路由：单目标退化为官方策略行为
  • 限额过滤：超 TPM/RPM 的部署被排除
  • 冷启动：无历史数据的部署仍参与评分
  • 平局随机：同分部署随机选择，不长期锁定单点

测试验证了纯成本路由在「免费本地模型 vs 付费云端模型」对比中正确选择免费模型，在云端模型间正确选择更便宜的 gpt-4o-mini——说明成本解析和归一化逻辑是真实生效的，不是纸面设计。

6结论与下一步

  • ✓ 突破单一目标限制：四维加权让业务偏好可配置，一套网关适配多种任务。
  • ✓ 工程细节完整：冷启动、限额过滤、平局随机、权重归一化，都是真实环境会踩的坑。
  • ✓ 走官方扩展点：与 LAR-1 同构，不碰路由主流程，可维护、可评审。
  • ✓ 测试锁行为：18 个单测覆盖主要分支，单目标退化为官方行为。
这次 fork 的收获是「怎么给一个成熟项目加能力而不破坏它」：找对扩展点、尊重既有模式、把边界情况（冷启动、限额、平局）都想到。下一步方向：接入真实多模型网关跑一轮线上对比数据、把指标采集改成滑动窗口（而不是累计）、支持按请求动态传权重。
