一句话结论给微软 MarkItDown（60k+ star 文档转换工具）修了一个真实 issue（#53）：Excel 里显示 $1,199.00 的单元格，转成 Markdown 后只剩 1199。根因是 pd.read_excel 只读单元格值、不读格式元数据。我按维护者要求的 config 对象模式 设计了 opt-in 的 XlsxConfig(preserve_formatting=True)，动态提取货币符号并渲染货币/百分比/千分位/日期格式，默认行为完全向后兼容。PR 见 microsoft/markitdown#2347。

1问题：Excel 转 Markdown，格式去哪了

MarkItDown 是微软开源的「万物转 Markdown」工具，Excel、Word、PDF、图片都能转。用它把一份带格式的 Excel 转成 Markdown 做知识库入库，是很常见的用法。但很快会发现一个诡异的现象：

Excel 里显示转出来的 Markdown丢了什么
$1,199.001199货币符号、千分位、小数位
25.5%0.255百分比语义
2024-01-1545241日期格式（Excel 序列号）
€9.509.5币种

对「人读」来说，1199 和 $1,199.00 差的不只是符号——货币、百分比、日期这些语义信息全丢了。对 RAG 检索来说，0.255 和 25.5% 检索语义完全不同。这就是 issue #53 报告的问题。

2定位根因：pd.read_excel 只读值不读格式

MarkItDown 的 XLSX 转换走的是 pandas：pd.read_excel() 读 DataFrame，再逐行转 Markdown。问题就出在这一层——pandas 只读单元格的原始值，不读格式元数据。

Excel 文件里每个单元格其实有两层信息：value（存储值，比如 1199）和 number_format（显示格式，比如 "$"#,##0.00）。Excel 界面显示的是「存储值套上格式」的结果。pandas 只取前者，格式串在转换途中被丢弃。

复现脚本写一个 repro_53.py：用 openpyxl 造一个带 "$"#,##0.00 格式的单元格，再走 MarkItDown 转换，输出确实是 1199。再用 openpyxl 直接读同一个文件，cell.number_format 能拿到 "$"#,##0.00——格式元数据一直在文件里，只是转换链路没读它。根因清楚了。

修法方向也清楚了：转换时用 openpyxl 读取 number_format，把「存储值」渲染成「显示值」。但这里有个关键约束——不能破坏默认行为。

3方案设计：为什么是 XlsxConfig 而不是布尔参数

最直觉的做法是给 XlsxConverter 加一个 preserve_formatting: bool = False 参数。但 MarkItDown 维护者在既有 PR #1325 的评审里明确要求过：用 config 对象，不要用布尔参数。原因很实际：

  • 可扩展：未来要加「日期格式」「千分位开关」等选项，config 对象直接加字段，布尔参数会让构造函数参数无限膨胀。
  • IDE 友好：XlsxConfig(preserve_formatting=True) 有自动补全和类型提示，裸布尔参数没有。
  • 模式统一：后续 PdfConfig、DocxConfig 都按同一模式走，整个库的配置风格一致。
@dataclass
class XlsxConfig:
    """Configuration options for :class:`XlsxConverter`."""
    preserve_formatting: bool = False  # 默认关闭，保持向后兼容

class XlsxConverter(DocumentConverter):
    def __init__(self, config: Optional[XlsxConfig] = None):
        super().__init__()
        self._config = config or XlsxConfig()

    def convert(self, file_stream, stream_info, **kwargs):
        if self._config.preserve_formatting:
            return self._convert_with_formatting(file_stream, **kwargs)
        # 默认走原 pandas 路径，输出与旧版完全一致

关键决策是 默认关闭。为什么？开启后输出会带 $、,、% 等字符，下游如果写 float(cell_value) 解析会直接崩。默认关闭保证既有用户零感知，只有显式开启才走新的格式化路径——这是「向后兼容」的工程底线。

4实现细节：货币符号动态提取 + 格式渲染

真正花功夫的是把 number_format 字符串翻译成可读文本。Excel 的格式串是它自己的 DSL，比如 "$"#,##0.00、0.00%、[$€-407]#,##0.00。我实现了一个轻量解析器，处理四类格式：

格式类型格式串示例渲染结果
货币"$"#,##0.00 / [$€-407]#,##0.00$1,199.00 / €1,199.00
百分比0.00%25.50%
千分位#,##01,234
日期yyyy-mm-dd2024-01-15

两个容易踩的细节：

  • 货币符号不能硬编码：从格式串里正则提取引号字面量（"$"、"€"）和 [$USD] 货币代码，动态识别符号。这样美元、欧元、人民币都能正确输出，而不是写死一个 $。
  • 负数会计格式：格式串含括号（会计格式）时输出 ($1,234.50)，标准格式输出 -$1,234.50。符号位置也要自适应："$"#,##0.00 符号前置，#,##0.00"€" 符号后置。
使用方式启用只需一行：MarkItDown(xlsx_config=XlsxConfig(preserve_formatting=True))。XlsxConfig 已从 markitdown 包顶层导出，IDE 自动补全友好。

6结论与下一步

  • ✓ 从现象到根因：pandas 只读值不读格式元数据，格式串一直在文件里，是转换链路没读它。
  • ✓ 遵循维护者模式：用 config 对象而非布尔参数，可扩展、IDE 友好、风格统一。
  • ✓ 向后兼容：默认关闭，既有用户零感知；显式开启才走格式化路径。
  • ✓ 有测试无回归：8 个新测试 + 既有测试向量全通过。
这次贡献最有价值的不是那 294 行代码，而是「怎么在不破坏别人的前提下加功能」——opt-in 配置、默认向后兼容、测试锁回归，这套工程习惯在任何项目里都通用。下一步方向：把格式解析扩展到 Word 表格、支持更多 Excel 格式串（科学计数、文本前缀），以及把格式化路径的覆盖测试补到 20+。
